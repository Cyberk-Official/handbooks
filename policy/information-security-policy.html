Information Security Policy

Re: Issuance of the Information Security Policy (ISP), applicable to all employees and contractors at CYBERK CO., LTD.

Article 1. This Decision promulgates the attached "Information Security Policy (ISP)", applicable to all employees and contractors at CYBERK CO., LTD.
Article 2. This Decision takes effect from the date of signing. Any previous provisions contrary to this Decision are hereby repealed.
Article 3. All Department Heads and the CTO shall be responsible for implementing this Decision. Any violation will be handled in accordance with internal regulations.

1. Account Security

1.1. Two-Factor Authentication (2FA)

  • Mandatory 2FA for all of the following accounts: company email, GitHub, cloud services (AWS, GCP, Azure, etc.), and any account used for company projects.
  • Accepted 2FA methods: authenticator apps (Google Authenticator, Microsoft Authenticator, Authy), hardware security keys (YubiKey, Titan Security Key), or biometric authentication when available.

1.2. Password Requirements

  • Use a strong, unique password for each account. Recommended: use a password manager (1Password, Bitwarden, LastPass).
  • Minimum length: 12 characters. Must include uppercase, lowercase, numbers, and special characters.
  • Change passwords every 6 months (180 days) or immediately if compromise is suspected.

1.3. Phishing Awareness

  • Always verify sender emails and suspicious links before clicking.
  • Never provide login credentials or personal information through unverified links.
  • Report phishing emails to management immediately.

2. Device Security

2.1. Encryption Requirements

  • All work devices must have full-disk encryption enabled: macOS: FileVault, Windows: BitLocker, Linux: LUKS.
  • Encryption recovery keys must be stored in a secure location, separate from the device.

2.2. Access Control

  • Strong password/passphrase required for device login.
  • Auto-lock screen after 5 minutes of inactivity.
  • Install all security updates and OS patches as soon as available.

2.3. Lost or Stolen Devices

  • Report immediately to management when a device is lost or stolen.
  • The company will execute remote lock and wipe procedures when possible.

3. Physical Document Management

3.1. Paper Document Policy

  • Prioritize digital documents over paper.
  • Paper documents containing sensitive information must be shredded before disposal.
  • Sensitive documents must not leave company premises without management approval.
  • Must be stored in locked cabinets when not in use.

4. Sensitive Data Management

4.1. Keys & Secrets Management

  • ABSOLUTELY PROHIBITED to store sensitive keys (secret keys, API keys, private keys), passwords, or credentials in: GitHub repositories (including private repos), public cloud storage (Google Drive, Dropbox), unencrypted local storage, or messaging apps (Slack, Discord, Zalo) and email.

4.2. Recommended Practices

  • Environment variables (.env): Use .env files for local development and ensure they are added to .gitignore.
  • Secrets Vault: Use dedicated services such as AWS Secrets Manager, HashiCorp Vault, Azure Key Vault, or Google Secret Manager.
  • .gitignore: Ensure sensitive files (*.pem, *.key, credentials.json, .env) are always declared in .gitignore.
  • Source code scanning: Deploy automated scanning tools (git-secrets, truffleHog) in CI/CD pipelines to detect accidentally committed secrets.
  • Principle of Least Privilege: Grant access to keys and secrets only to those who genuinely need it.

4.3. API & Database Security

  • Always use secure connection strings (e.g., via SSL/TLS).
  • Implement Role-Based Access Control (RBAC) to limit data access.
  • Rotate access keys periodically.
  • Log all access and critical actions.

5. Client Data Protection

5.1. Data Storage & Access

  • Client data may only be stored in approved, security-configured cloud environments.
  • Prohibited to store client databases or data copies on personal computers.
  • Do not share client data outside authorized systems.
  • Data access logs must be maintained and reviewed regularly.

5.2. Data Transmission

  • Use secure protocols for all data transmission (HTTPS, SFTP, TLS).
  • Encrypt all data in transit.

5.3. Data Lifecycle

  • Establish retention and deletion policies for client data upon contract expiration or upon request.

6. Software Security

6.1. Software Installation Policy

  • Only install software from verified and trusted sources (official websites, App Store).
  • Prohibited: software from unknown sources, applications flagged as dangerous by the OS, and cracked or pirated software.

6.2. Updates & Dependency Management

  • Keep all OS and installed software up to date.
  • Enable automatic security updates when possible.
  • Regularly scan project libraries and dependencies for vulnerabilities (e.g., npm audit, GitHub Dependabot).

7. Network Security & Connectivity

7.1. Wi-Fi Usage

  • Prioritize wired (Ethernet) or secured company Wi-Fi connections.
  • When working remotely, avoid unprotected public Wi-Fi. Use company VPN if necessary.

7.2. VPN

  • All remote connections to internal company resources must be made through an approved VPN.

8. Security Incident Response

8.1. Reporting Procedure

  • Any employee who discovers or suspects a security incident (e.g., lost device, compromised account, malware) must report immediately to their direct manager or security team.

8.2. Responsibilities

  • Do not attempt to resolve incidents independently. Follow instructions from the technical team to avoid further damage.
  • Cooperate fully during investigation and remediation.

9. Blockchain & Crypto Security

9.1. Private Key & Seed Phrase Management

  • Core principle: Private keys and seed phrases are critical assets. Losing them means losing all wallet assets permanently.
  • ABSOLUTELY PROHIBITED to store private keys or seed phrases in unencrypted digital form on any device, cloud service, email, or messaging app.
  • Top priority: Use cold wallets (Ledger, Trezor) for important assets and high-value transaction signing.
  • Physical backup of seed phrases must be stored in extremely secure locations (fireproof safe, bank deposit box) and may be split into parts if necessary.
  • Hot Wallets: Use only for daily operations with small amounts. Never import cold wallet seed phrases into hot wallets.

9.2. Smart Contract Safety

  • Audit: All smart contracts must be audited by at least one independent, reputable third party before mainnet deployment. All discovered vulnerabilities must be resolved.
  • Prioritize well-known, community-vetted libraries (OpenZeppelin, SafeMath).
  • Testing: Comprehensive test suites including unit tests, integration tests, and fuzz testing. Deploy on testnet and invite community testing before production.
  • Consider launching a bug bounty program post-deployment.

9.3. Safe Interaction with Protocols & dApps

  • Always verify contract addresses on reputable block explorers (Etherscan, BscScan) before interacting.
  • Exercise extreme caution with "airdrop" or "minting" messages on social media (Discord, Telegram, Twitter). Never click unknown links or scan unknown QR codes.
  • Regularly review and revoke unnecessary token approvals using tools like Revoke.cash.
  • Use burner wallets with small balances to interact with new or unvetted protocols.

9.4. Infrastructure & Node Security

  • If operating self-hosted nodes, RPC endpoints must not be publicly exposed without strict security measures.
  • Limit node server access to trusted IP addresses only.
  • Keep all clients (Geth, Prysm, etc.) updated to the latest version to patch known vulnerabilities.

10. AI Safety

10.1. Approved AI Tools

  • Employees may use personal or company-provided AI accounts for work.
  • Only use genuine AI accounts purchased directly from original providers: Google Gemini, Anthropic Claude, OpenAI, or company-provided APIs.
  • Prohibited: AI APIs sold or distributed by third parties, AI proxy services, or any non-official intermediary.

10.2. Protecting Sensitive Information

  • ABSOLUTELY PROHIBITED to provide AI tools with: private keys, seed phrases, environment variables (.env), passwords, authentication tokens, or API keys.

11. Software Licensing

  • Prohibited: installing or using cracked, pirated, or unlicensed software on work devices.
  • Prohibited: using tools, software, or licenses sold or distributed by unauthorized third parties.
  • Do not use bypass methods or any form of license circumvention.
  • All software used for work must be purchased or registered directly from official providers, or licensed by the company.
Note: This document should be reviewed and updated annually or when significant changes in technology, processes, or security requirements occur. Section 10 (AI Safety) should be reviewed more frequently (at least every 6 months) due to the rapidly evolving AI landscape.
